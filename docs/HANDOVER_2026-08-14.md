## 2. 1.2.2 发布内容

版本 `1.2.2 / 1002002`，bundle `com.vintage.pomelopro`，显示名 `旧柚Pro`，API 23（compatible=target=23），ARM64。

本次包含：

- **宿主键盘输入法支持**（本会话核心成果）：
  - compositor 新增 `zwp_text_input_manager_v3` 服务端，enter/leave 完全跟随 `InputManager` 的键盘焦点（与 `wl_keyboard.key` 注入同源，不再有第二套焦点状态）；
  - NAPI：`wineTextInputPreedit/Commit/Enabled/SetArmed`，preedit/commit 经 pipe 封送到 Wayland 线程发送；
  - ArkTS 桥：隐藏 `TextInput` + 单字符哨兵 + 前缀/后缀差分；ASCII/退格/回车走虚拟键盘同一条 `pressKey` 路径；
  - 已修复：管道读端阻塞导致卡死、切换控件后退格偶发丢失（ForEach 复用键漏 `widthScale`、range 上报漂移）、收起键盘误注入退格。
- **UI 修复**：编辑器顶部按钮恢复原 ✕（退出）；属性面板去掉 X 与折叠按钮，选中显示、点空白自动隐藏、标题栏可拖动；缩放 10–500%、按键宽度 20–1200% 且拖动实时预览；各分类滚动位置在页面切换后保持；Windows 卡片去掉 Download 角标；记事本加入内建应用；IE/记事本图标更换。
- **Box64 兼容预设**：已确认生效（选“稳定模式”后新启动进程环境实际变为 `SAFEFLAGS=2 / BIGBLOCK=0 / FORWARD=128` 等），只影响新启动的进程。

## 4. 宿主输入法实现要点

关键文件：

```text
entry/src/main/cpp/text_input.{h,cpp}                        # text-input v3 服务端
entry/src/main/cpp/text-input-unstable-v3-protocol.c         # 协议编解码（生成物）
entry/src/main/cpp/include/text-input-unstable-v3-server-protocol.h
entry/src/main/cpp/input_manager.cpp                         # KBD_ENTER/LEAVE 挂钩
entry/src/main/cpp/wl_core.cpp                               # global 注册 + surface 销毁清理
entry/src/main/cpp/napi_init.cpp                             # NAPI 导出
entry/src/main/ets/pages/InputOverlay.ets                    # 隐藏 TextInput + 哨兵桥
entry/src/main/ets/components/VirtualInputOverlay.ets        # 元素 ForEach 复用键、widthScale 渲染
entry/src/main/ets/common/KeyMap.ets                         # ASCII→evdev 映射
```

设计原则：text-input 的 enter/leave 必须与键盘注入完全同源（同一个 `keyboardFocusedSurface_`），preedit/commit 只在 Wayland 线程发送；ASCII/退格/回车一律走 `InputDispatcher.pressKey`。细节见 `docs/host-ime-design.md`。

已知边界：系统键盘的候选窗定位未做；“切换控件后退格偶发丢失”已用鲁棒差分修复，仍需长期观察；键盘唤起后窗口压缩/避让未启用。


关键脚本：`scripts/build_gstreamer.sh`、`scripts/build_gnutls.sh`、`scripts/assemble.sh`、`scripts/env.sh`。

打包侧关注点：

- `wine-data.zip` 内的 GStreamer 插件链（base/good + FFmpeg/gst-libav）；
- 插件 `.so` 是否同时有“无版本名”（box64 按名 dlopen 必需）；
- `libintl.so.8` 等运行时依赖是否入库；
- `wine_runtime.version` 标记（`entry/src/main/resources/rawfile/wine_runtime.version`）；
- 子进程环境里的 `GST_PLUGIN_PATH` / `GST_PLUGIN_SYSTEM_PATH` / `BOX64_EMULATED_LIBS`（含 gstreamer 系列库）。

### 当前已知状态

- 子模块 gitlink 干净；只有 `subprojects/.wraplock` 未跟踪（meson 生成物）。
- 1.2.2 包内已确认包含 guest-gfx 与 wine-data.zip，但**尚未针对具体 GStreamer 故障做专项验证**。

### 交接人需要补的信息（在其他工具里开工前先明确）

1. 具体现象：是插件加载失败（`no such file` / plugin not found）、解码失败（黑屏/无声）、`winegstreamer` dlopen 失败，还是进程崩溃？
2. 复现路径：哪个应用/格式？直接播本地文件还是网络流？
3. 影响范围：只影响播放，还是影响启动/整体稳定性？

### 建议调查顺序

1. 设备上复现并抓日志：`hilog` 过滤 `gst|winegstreamer|GLib|GStreamer`，同时取 `wine_stderr_*.log`。
2. 核对运行时解压后的插件目录与 `.so` 存在性、命名（无版本名）、依赖（用 `readelf -d` 看 NEEDED）。
3. 核对子进程 env：`GST_PLUGIN_PATH`、`GST_PLUGIN_SYSTEM_PATH`、`BOX64_EMULATED_LIBS`、`LD_LIBRARY_PATH`。
4. 对照 `090cf1b` merge 与 `build_gstreamer.sh` 的实际产物，确认 1.2.2 包的插件链与 1.2.1 是否一致。
5. 修改子模块前先记录当前 SHA，且**不要用 `git checkout` 清理 `.wraplock`**（属用户工作区状态）。
